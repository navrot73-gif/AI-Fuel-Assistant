# 🚗 AI Fuel Assistant - Контекст проекта и Архитектура

## 📱 О проекте
**AI Fuel Assistant** — это Android-приложение для поиска ближайших АЗС, сравнения цен и получения аналитики на базе искусственного интеллекта. 
Приложение использует мульти-AI роутер (DeepSeek, GigaChat, YandexGPT, HuggingFace) для анализа рынка топлива и построения оптимальных маршрутов.

## 🛠 Технологический стек
* **Язык:** Kotlin
* **UI:** Jetpack Compose, Material 3 (с поддержкой Dark Theme)
* **Картография:** OSMDroid
* **Архитектура:** MVVM + Clean Architecture элементы (Repository pattern, UseCases)
* **DI:** Hilt
* **Сеть:** OkHttp (единый клиент через DI, таймауты 30с), Retrofit
* **Локальное хранение:** Room, DataStore
* **Фоновые задачи:** WorkManager
* **Геолокация:** FusedLocationProviderClient, Nominatim (Geocoding), OpenRouteService (Routing)

## ✅ Реализованные улучшения и исправленные баги (Спринт "Рефакторинг")

### 🔴 Критические баги (Исправлено)
1. **Крэш на Android 7.x (API 24-25):** Заменен `java.util.Base64` на `android.util.Base64` в `GigaChatAiProvider`.
2. **Хардкод координат:** Удален хардкод Челябинска в `MapViewModel` при переключении типа топлива. Теперь используется `StateFlow` с реальными координатами пользователя.
3. **Кнопка "Моё местоположение":** FAB на карте теперь корректно вызывает `animateTo()` для центрирования на пользователе.

### 🟡 Архитектура (Улучшено)
1. **Единый источник правды:** `DashboardViewModel` (AI-аналитика) теперь загружает АЗС через `GasStationRepository`, а не использует хардкод `DemoFuelStations`.
2. **Сетевой слой:** Все AI-провайдеры инжектируют единый `OkHttpClient` через Hilt (общий пул соединений, корректные таймауты).
3. **DRY (Don't Repeat Yourself):** Формула Хаверсина вынесена в единый `GeoUtils.kt`, дубликаты удалены из `MapHelpers` и `GasStationRepository`.
4. **WorkManager:** Настроен `StationUpdateWorker` для фонового обновления кэша АЗС.
5. **Темы:** Настроена автоматическая поддержка `isSystemInDarkTheme()` в `Theme.kt`.

## 🚀 Roadmap (Что нужно сделать дальше)

### 1. Интеграция написанных геосервисов (Высокий приоритет)
* **Проблема:** Классы `NominatimGeocodingProvider.kt` и `OpenRouteServiceProvider.kt` написаны, но не используются. В `MapHelpers.kt` координаты определяются через хардкод (`when (lat in ...)`).
* **Задача:** Подключить Nominatim для обратного геокодирования (определения улицы/города по координатам) и OpenRouteService для построения реальных линий маршрута на карте OSMDroid.

### 2. Оптимизация AI Router (Fallback-механизм)
* **Задача:** Реализовать механизм "гонки" (race condition) для `AiRouter`. Отправлять запросы в несколько LLM параллельно (или с минимальным таймаутом) и брать первый успешный ответ, чтобы не ждать падения первого провайдера.

### 3. Выделение UseCases и чистое тестирование
* **Проблема:** Тесты `GasStationRepositoryTest` тестируют скопированную локальную логику, а не реальный код.
* **Задача:** Вынести логику фильтрации и сортировки АЗС в чистые Kotlin-классы (UseCases), не зависящие от Android `Context`, и покрыть их Unit-тестами.

### 4. Поддержка нескольких авто
* **Задача:** Доработать UI и `DashboardViewModel`, чтобы пользователь мог выбирать активный автомобиль для AI-анализа, а не только брать `firstOrNull()`.
