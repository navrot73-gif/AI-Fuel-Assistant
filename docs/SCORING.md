# Скоринг АЗС

> Текущая реализация: [`app/src/main/java/com/navrot/aifuelassistant/domain/usecase/GetBestStationsUseCase.kt`](../app/src/main/java/com/navrot/aifuelassistant/domain/usecase/GetBestStationsUseCase.kt)
> При изменении формулы — обновляйте и этот файл.

## Назначение

Composite score нужен, чтобы выдать пользователю **одну лучшую АЗС** с учётом нескольких противоречивых факторов: дешёвая, но далеко и с очередью — хуже, чем чуть дороже, но рядом и без очереди.

**Инвариант:** чем меньше score — тем лучше АЗС.

## Формула

```
score = fuelPrice * PRICE_WEIGHT
      + queueTime * QUEUE_WEIGHT
      + (100 - reliability) * RELIABILITY_WEIGHT
      + distanceKm * DISTANCE_WEIGHT
      + (NO_FUEL_PENALTY if availability == NO_FUEL else 0)
```

## Веса (из `ScoringWeights`)

| Константа | Значение | Смысл |
|-----------|----------|-------|
| `PRICE_WEIGHT` | `1.0` | Базовая цена за литр, руб. |
| `QUEUE_WEIGHT` | `0.5` | 1 минута очереди ≈ 0.5 ₽ штрафа |
| `RELIABILITY_WEIGHT` | `0.2` | 1 пункт ненадёжности цены ≈ 0.2 ₽ штрафа |
| `DISTANCE_WEIGHT` | `1.2` | 1 км от пользователя ≈ 1.2 ₽ штрафа |
| `NO_FUEL_PENALTY` | `1000.0` | Жёсткий штраф за `NO_FUEL` |

Все веса лежат в `ScoringWeights` и инжектятся через Hilt. Это позволяет в будущем вынести их в Remote Config или A/B-тест без правки логики.

## Компоненты

### fuelPrice
Цена за литр нужного типа топлива (`fuelType`). Берётся из `station.fuelTypes.find { it.type == fuelType }`. Если у станции нет такого типа — станция **отфильтровывается** до скоринга (не участвует в выдаче).

### queueTime
Время в очереди в минутах. Источник:
- User report (самое свежее)
- Benzonavt / сеть
- Если данных нет — `0` (штраф не накладывается)

### reliability
Процент надёжности цены (0..100) из `PriceReliabilityCalculator`:
- `USER_CONFIRMED` — 95%
- `NETWORK` (Benzonavt / Russiabase) — 85%
- `CACHE` — 70%
- `ASSETS` — 40%
- Штрафы: −5 за 1-3 дня, −15 за 4-7 дней, −30 за >7 дней
- Бонусы: +10 если несколько источников, +5 если есть фото-доказательство

Чем **ниже** reliability → тем **выше** `(100 - reliability)` → тем **больше** штраф.

### distanceKm
Расстояние от пользователя по Haversine (`GeoUtils.calculateDistance`). Если не передано — `0` (например, при выдаче «топ-10 дешёвых в городе» без учёта позиции).

### availability
Статус из `PriceReliabilityCalculator.calculateFuelAvailability`:
- `AVAILABLE` — топливо есть, свежесть в пределах 8 ч (или 24 ч для Russiabase)
- `NO_FUEL` — топлива нет ИЛИ станция закрыта (свежесть ≤ 24 ч для Russiabase)
- `UNKNOWN` — данных нет или устарели

Если `NO_FUEL` → добавляется жёсткий штраф `+1000`. **Станция не скрывается** (пользователь может видеть «нет 95-го, но есть 92-й»), но уходит в конец списка.

## Примеры

### Пример 1: Станция А vs Станция Б
| Параметр | А | Б |
|----------|---|---|
| Цена АИ-95 | 65 ₽ | 67 ₽ |
| Очередь | 5 мин | 0 мин |
| Надёжность | 85% | 85% |
| Расстояние | 1 км | 3 км |
| Статус | AVAILABLE | AVAILABLE |

```
А: 65*1.0 + 5*0.5 + (100-85)*0.2 + 1*1.2 + 0 = 65 + 2.5 + 3 + 1.2   = 71.7
Б: 67*1.0 + 0*0.5 + (100-85)*0.2 + 3*1.2 + 0 = 67 + 0   + 3 + 3.6   = 73.6
```

**А лучше** на 1.9 балла — дешевле на 2 ₽, но с очередью 5 мин. Стоит ли ехать — вопрос пользователя. Можно подсветить обе в карточке.

### Пример 2: Влияние статуса NO_FUEL
Та же станция А, но `NO_FUEL`:
```
А: 71.7 + 1000 = 1071.7
```

Станция не пропадает, но в топе её уже не будет.

### Пример 3: Влияние надёжности
Станция В: цена 60 ₽ (самая дешёвая), но цена только из assets:
- reliability = 40% → штраф = (100-40)*0.2 = 12
```
В: 60*1.0 + 0 + 12 + 0.5*1.2 + 0 = 72.6
```

Дорогая станция Б (67 ₽) с надёжностью 85% оказывается хуже на **1 балл**. Это сигнал: «дешёвая станция с непроверенной ценой может оказаться не дешёвой».

## Где вызывается

| Метод | Что делает |
|-------|------------|
| `GasStationRepository.getBestStations()` | Топ станций по composite score в радиусе |
| `DashboardViewModel.StationRecommendationDelegate` | Подбор «лучшей АЗС» для дашборда |
| `MapViewModel.MapFilterDelegate` | Сортировка по composite в bottom-sheet |

## Где НЕ используется

- `sortPriceAscending` / `sortPriceDescending` — простая сортировка по цене, для пользователей, которым важна только цена
- `sortByQueue` — только очередь
- `getCheapestStation` — без скоринга, чисто min(price)

## Тюнинг весов

Идеи для будущих итераций (НЕ сделано):
1. **Учёт типа клиента**: для такси/доставки важнее очередь и расстояние, для дачника — цена
2. **Время суток**: ночью очередь не важна (нет очередей), днём — наоборот
3. **Погода** (через OpenWeather): в −30 очередь важнее, потому что ждать на морозе дороже
4. **A/B-тест**: вынести веса в Remote Config, проверять конверсию «открыл карточку → поехал на заправку»
